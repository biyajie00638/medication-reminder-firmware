# 我给爸妈做了一个会说话的“吃药闹钟”

家里长辈上了年纪，每天要吃的药常常不止一种：什么时间吃、吃多少，光靠记性很容易漏。我也试过在手机上设闹钟、在冰箱贴纸条，但老人家对着智能手机往往不知道点哪里，纸条又容易被忽略。

于是我动手做了一个**专门给长辈用的用药提醒小盒子**：到时间了，屏幕上大大地显示药名和用量，同时用真人般的中文语音反复播报；吃完按一下键，说一句“吃过了”，它就记下来。更重要的是，万一哪天家里换了路由器、WiFi 变了，不用插电脑、不用拆机，我在网页上改一下密码，盒子自己就重新连上了。

这个项目从想法到做出来，前后折腾了不少嵌入式和服务端的坑。今天把它整理出来，代码也完全开源，方便有同样需求的朋友直接拿来用、拿去改。

## 一、它到底能做什么

- ⏰ **定时提醒**：每 60 秒跟服务端对一下表，自动匹配“现在该吃哪一顿”
- 🖥️ **大字显示**：320×240 的小屏，黄色药名 + 白色用量，老人一眼就看清
- 🔊 **语音播报**：每条提醒循环念 5 遍，用的是微软 edge-tts 的中文女声，不是机械的“嘀嘀嘀”
- ✅ **语音确认**：按一下顶上的按键，说一句“我已经吃了”，盒子把声音传上去识别，确认完成
- 📶 **WiFi 远程改密**：家里 WiFi 一变，网页上点几下，盒子自动重连；连不上还会自己退回原来的网络，绝不变砖

## 二、硬件就一块开发板

核心是一块 **ESP32-S3-BOX-3**（乐鑫官方开发板，自带屏幕、喇叭、麦克风），官方渠道几十块钱就能搞定。屏幕是 ILI9341，音频芯片是 ES8311（喇叭）+ ES7210（麦克风）。整块板子插电就能用，不需要额外接线、不需要焊电路。

成本很低，关键是**全开源、可自己改**。

## 三、整体怎么跑起来的

整个系统分两头：盒子只负责“显示 + 播音 + 录音”，所有逻辑（服药计划、语音合成、语音识别）都放在服务端。这样盒子本身很轻，要加功能主要改服务端就行。

```
   [用药提醒盒子 ESP32]
        │  每 60 秒 HTTP 轮询
        ▼
   [服务端 medication-server]   ← Docker 部署，任意一台电脑 / 云服务器
        │  管理服药计划 / 生成语音 / 语音识别 / 下发 WiFi
        ▼
   [网页管理后台]   ← 手机 / 电脑浏览器打开，就能增删计划、改 WiFi
```

## 四、几个踩过的坑（技术彩蛋）

做的过程中有几个挺有意思的坑：

1. **中文显示**：这块小屏的默认字库只有英文，中文会显示成空白。我离线生成了一套 16×16 的中文点阵字库（七千多个常用字）烧进 Flash，终于能在资源极其紧张的单片机上显示中文药名。
2. **全双工音频**：喇叭和麦克风共用一组 I2S 时钟，一开始要么没声、要么录不到，最后用“单端口全双工”架构解决——一个时钟同时驱动放音和收音。
3. **时区陷阱**：服务端跑在 Alpine 容器里，默认不认中国时区，导致提醒时间整整差了 8 小时。最后在镜像里装了 tzdata 并固化 `Asia/Shanghai` 才彻底解决。
4. **WiFi 变了的焦虑**：老人不会配网。所以做了“服务端下发新 WiFi → 盒子自动重连 → 失败回退”的闭环，彻底免去了现场折腾。

## 五、想自己做一个？

两套代码都已开源，MIT 协议，随便用、随便改：

- 🔧 固件（ESP32）：https://github.com/biyajie00638/medication-reminder-firmware
- 🖥️ 服务端：https://github.com/biyajie00638/medication-server-

部署也不复杂：服务端用 Docker 一条命令起好；固件填一下 `config.h`（WiFi、服务器地址、设备 MAC），用 PlatformIO 编译烧录即可。仓库 README 里每一步都写好了。

## 六、一点说明

这个小盒子是给家人用的**辅助提醒工具**，不是医疗器械。网络中断、意外断电等情况都可能让它偶尔“失声”，重要用药请仍以医生嘱咐和家人照看为准。把它当作一个温柔的“第二道保险”就好。
